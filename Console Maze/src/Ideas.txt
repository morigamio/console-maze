● A few new directions, scoped small:

  1. Random treasure & start position each game — picks a non-wall cell using std::mt19937 (you'd finally use
  <random> in production code). Instant replay value, ~10 lines in reset().
  2. Step counter HUD — track int steps on successful moves, print it above the map. Sets up the idea of a "score"
  you can later turn into a high-score file.
  3. Step limit → wire up the LOSE state — you already have LOSE in the enum, unused. Give the player N steps;
  running out = lose. Adds tension and finally retires that dead enum value.
  4. Footprint trail — std::deque<std::pair<int,int>> of the last ~8 positions, rendered as faded ·. New container,
   satisfying breadcrumb effect.

  If you want one feature that teaches new C++ and changes how the game feels, #1 (random spawn) is the pick —
  every restart becomes a fresh puzzle, and you get hands-on with <random> proper. If you want the most "complete
  game" feel for least effort, #3 (step limit / lose state) turns this from a maze into an actual challenge.
